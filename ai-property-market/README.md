# AI Property Market

**Данни за българския пазар на недвижими имоти — pipeline за
нормализиране, дедупликация и търсене, написан на Python и
ориентиран към тестове.**

Проектът е **некомерсиален хоби проект**. Не продава нищо, не
регистрира потребители, не събира лични данни.

## За проекта и AI асистента

Това е **проект, направен от мен с AI асистент**. Аз съм
замислил архитектурата, съм определил какво поведение трябва да
работи и кое поведение е недопустимо, съм описал всеки дефект в
момента, в който е написан тестът да го предотврати, и съм
преглеждал резултата на всяка стъпка.

Асистентът е написал кода по тези инструкции. Решенията — **какво
да се тества, защо точно този тест, какво е истински дефект и
какво да се смята за приемливо** — са мои.

Това е единственият проект в репозитория, направен с AI. Останалите
папки (C# suite-ите, ръчните тесткейсове, Postman колекциите) са
моя собствена работа от обучението ми по QA и по лична инициатива.

## Какво прави продуктът

Пазарът на недвижими имоти у нас е разпръснат: държавни
геопортали, общински регистри, статистически публикации. Всеки
източник говори на свой диалект — различни имена на полета,
различни единици, различен формат, понякога кирилица, понякога
ASCII, понякога стойност в квадратни метри, понякога в
километри.

Този проект взема **сурови данни от различни източници** и ги
превръща в **един-единствен, почистен и търсим набор**:

```
RAW снимка
   ↓  normalizer.py        открива формата, извлича цена и площ,
   │                       превежда имената на полетата, отхвърля
   │                       записите, които изобщо не са имоти
   ↓  deduplicator.py      маха точните повторения (fingerprint)
   ↓  consolidator.py      свързва записите за един и същ имот от
   │                       различни източници (entity matching + clusters)
   ↓  finished_exporter.py финален файл с история на цените
   ↓
search_api.py              Flask API + dashboard
```

### Пример

Суровият запис изглежда така:

```json
{ "properties": { "regname": "ж.к. Витоша - Планина",
                  "cena_ap": "429000.00", "area_kv_m": 67 } }
```

Нормализираният и валидираният изход:

```json
{ "property_id": "prop_33",
  "attributes": { "regname": "ж.к. Витоша - Планина", "kvartal": "Витоша" },
  "price": 219337.42,
  "area_m2": 67.0,
  "price_history": { "current_price": 219337.42, "delta_all": 4.1 },
  "location": { "geometry": { "type": "Point", "coordinates": [23.31, 42.69] } } }
```

Същото поле е станало `price` (конвертирано BGN → EUR),
`area_m2` е число вместо текст, името на квартала е извлечено
от свободния текст, а `property_id` е стабилен между два ръна
— което е точно условието, за да има история на цените.

## Как се стартира

Изисква се **само Python 3.10+**. Нищо друго не е нужно.

### Windows

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

startApp.bat
```

`startApp.bat` прави всичко: инсталира зависимостите ако
липсват, подготвя примерните данни, пуска pipeline-а и отваря
dashboard-а в браузъра на <http://127.0.0.1:5000/>.

### Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python main.py --demo
```

`--demo` е setup + pipeline + API в една команда.

### Стъпка по стъпка

```bash
python main.py --setup      # копира sample_data/ -> storage_raw/
python main.py --pipeline   # нормализиране -> дедуп -> експорт
python main.py --api        # dashboard на http://127.0.0.1:5000/
```

Всички команди са **без мрежа**. Виж следващия раздел.

## Мрежата е изключена

Проектът трябва да може да се клонира, прочете и пусне без
интернет, без да се теглят стотици мегабайти от чужди сървъри.
Затова **свалянето на данни е изключено по подразбиране**.

Един-единственото място, което решава това, е `netpolicy.py`.
Всяка точка на сваляне — трите колектора и fetcher-ът — минава
през `require_network()` и бискотен отговор при опит:

```
======================================================================
 --fetch-all: БЛОКИРАНО
======================================================================

Операцията сваля данни от външен източник.
Мрежата е изключена (netpolicy.py, AI_PROPERTY_ALLOW_NETWORK).
...
```

`--collect`, `--fetch-all`, `--fetch-ids` и `--full` са оставени
като аргументи, но **нарочно не правят нищо**. Ако някой ден
искате да ги пробвате за собствена употреба:

```bash
export AI_PROPERTY_ALLOW_NETWORK=1
```

По подразбиране проектът работи върху `sample_data/` — 35 обекта
в две снимки от София, достатъчни да покажат целия pipeline,
историята на цените и търсенето.

## Тестовете

Това е основният фокус на проекта. **680 теста, 0 мрежови
заявки, под 10 секунди.**

```bash
python main.py --tests
```

Или директно, ако предпочитате стандартните инструменти:

```bash
pytest                                    # цялата галерия
pytest --cov=tools --cov=collector        # с покритие
pytest -k area                            # само тестовете за площи
pytest --lf                               # само последните провали
```

### Windows, с доклад

```
tests\run_tests.bat
```

Прозорецът не се затваря сам. След ръна се печата доклад —
брой тестове по статус, реално време, най-бавни файлове, а при
провал пълният traceback. Числата идват от JUnit XML, а не от
разпарсване на текстовия извод, защото текстовият извод се
променя между версии, а XML форматът не се. Пълният доклад се
записва в `tests/_last_run/report.txt`.

Полезни аргументи:

```
tests\run_tests.bat tests\test_matcher.py   само един файл
tests\run_tests.bat -k area                 филтър по име
tests\run_tests.bat --no-wait               без чакане на клавиш
```

### Continuous integration

Галерията се пуска автоматично при всеки push и pull request
(`../.github/workflows/tests.yml`):

1. проверява, че `--collect` наистина е блокиран;
2. пуска pipeline-а върху вградения пример;
3. пуска 680-те теста и качва JUnit XML като артефакт.

### Защо толкова много

Всеки тест в `tests/` е написан за конкретен проблем, а не
за покритие на реда. Най-интересните от тях пазят **реални
бъгове, които вече са се случили**:

| Регресионен тест | Какъв бъг държи |
|---|---|
| `test_iter_json_records_preserves_numbers` | `ijson` без `use_float=True` връщаше `Decimal`; `json.dumps(default=str)` превръщаше всяко float в текст → **всички цени ставаха 0** |
| `test_location_is_not_an_address` | геометрията се приемаше за адрес → **25 825 фалшиви съвпадения** |
| `test_truncated_geojson_is_not_labelled_txt` | отрязана UTF-8 проба падаше при decode → **118 422 обекта мълчаливо отпаднали** |
| `test_load_finished_index_is_cached` | индексът се чешеше за всеки запис × прозорец → експортът висеше **над 30 минути** |
| `test_normalize_area_kvm_is_not_ar` | `area_kv_m` се умножаваше ×10 000 → 361 093 m² вместо 3 610 |
| `test_extract_price_bgn_converted` | BGN минаваше без конверсия → **двойно по-голяма цена** |
| `test_search_returns_numbers_not_strings` | същият `Decimal` проблем, този път в search API-то → филтрите по цена мълчаха |
| `test_agent_info_requires_token` | `/info` не валидираше токена → изток на чужди квоти |
| `test_export_twice_gives_same_property_ids` | нестабилен `property_id` → историята на цените се разрушаваше |
| `test_median_zone_area_is_outside_the_band` | лентата за правдоподобие пропускаше медианата |

Още десетки подобни са изброени в коментарите над
`tests/test_end_to_end.py` и в отделните тестови файлове.

### Тестовете не пипат реалните данни

`tests/conftest.py` насочва всички проекционни папки на
модулите към `tmp_path`. Има и мета-тест
(`test_no_network_in_suite.py`), който пази точно това условие —
защото веднъж един тест е записал в реалната `storage_raw/` и
саботирал пайплайна тихо, без да даде и една грешка.

## Какво НЕ е тук

Проектът е преминал през редица промени, преди да стана това,
което е. Умишлено е премахнато:

- **Плащания и PayPal.** Първоначалната версия имаше checkout,
  кредитна система, квоти и DEMO/PROD превключвател. Всичко
  това е премахнато — търсенето е отворено и безплатно, което е
  правилното за некомерсиален проект. Няма и лични данни, няма
  имейл на търговец, няма client_secret.
- **Свалянето на чужди данни по подразбиране.** Виж „Мрежата е
  изключена“.
- **Достъп до обявени портали.** Скрейпването на `alo.bg`,
  `imot.bg` и подобни е забранено от условията им, а
  извличането на цяла база е забранено от Закона за
  защитата на бази данни. Причината е документирана в
  [`collector/SOURCES_LEGAL.md`](collector/SOURCES_LEGAL.md) —
  заедно с проучените, но изключени по други причини, източници.
- **Будужето и изкуственият интелект в рантайма.** Няма модел,
  който да тегли тегла, няма API ключ, няма токен. „AI“ в името
  е за идеята за бъдещо приложение, не за извикване на външна
  услуга.

Това е съзнателно решение: проект, който прави изважане на чужди
данни или продава нещо, не е правилният проект да стои в
открит репозиторий.

## Технически решения

**Streaming навсякъде.** Големите GeoJSON файлове не се четат
в RAM. `ijson` ги обхожда запис по запис, а експортирането минава
през staging файл и два прохода. Един от тях е бил за 5 GB памет
за файл от 628 MB.

**Атомни записи.** Всеки файл се пише в `.tmp` и се преименува.
Прохватнато съединение по средата не оставя половин файл, който
следващият рън да прочете като валиден.

**Проверки за правдоподобие.** Нормалайзерът не вярва на
сляпото си. Площ от 361 093 m² за човешко жилище е подозрителна и
проверява се. Стойности, които минават само защото името на
полето съдържа подниз, се отхвърлят.

**Система, не скрипт.** Всеки етап има отделен модул с
еднозначен вход и изход. Това прави pipeline-а тестваем без
мрежа — и тестовете го доказват, вместо да го твърдят.

## Known limitations

Честно за какво този проект **не** става:

- **`area_kv_m` често не е площ на жилище.** В повечето набори
  на SofiaPlan това е площта на административна зона или
  квартал. Измерено върху реален snapshot от 297 170 записа:
  медианата е 9 499,7 m², а само 32,83% попадат в правдоподобната
  лента за жилище. Затова `metadata.json` на всяка снимка носи
  секция `area_plausibility` с тези бройки — **не за да филтрува,
  а за да не се чете средната площ като големина на апартамент**.
  Самите записи не се променят.
- **Дедупликацията между източници е изключена, докато има само
  един източник.** `content_fingerprint()` работи коректно само
  между различни източници; с един няма какво да сравнява. И
  това е правилно, а не пропуск.
- **История на цените изисква два ръна в различни моменти.**
  Име на снимка е `ден-месец-година_час`, затова два пускания
  в един и същи час презаписват един и друг файл, а не създават
  втора снимка. `price_history` се запълва при следващ рън в
  по-късен час — точно както би работило в реален проект, където
  колекторът тегли на всеки 12 часа. Тестовете го проверяват с
  изрично зададени timestamp-и (`test_export_parallel.py`), за
  да не зависят от това кое е часът.
- **Няма автентикация.** Търсенето е отворено и безплатно — по
  избор, не по недосвидност. Ако някой ден трябва да е
  публично в интернет, пред `/api/v1/search` трябва да се сложи
  нещо, преди да се сложи навън.

## Какво бих направил следващо

Ако проектът трябва да стане реален продукт, подредбата е:

1. **Договор с един обявен портал** за feed. Това е единственият
   законен начин за реални обяви за продажба — и е платено.
2. **Втори независим източник.** Дедупликацията и history-то
   имат смисъл само при повече от един източник; с един
   сравняваш самата себе си.
3. **Индексиране в搜索引擎** вместо линейно търсене по
   снимка.
